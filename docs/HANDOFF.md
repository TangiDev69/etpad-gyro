Exports ship with no original paks, installers, saves, downloaded servers' native modules, prebuilt macOS bot runtime or signing material. The default simulator and device now embed their source-built Omni-bot framework with verified script/navigation data. Default ANGLE and optional Vulkan simulator packages pass their final audits. The simulator ANGLE distributor frameworks contain x86_64 plus arm64; own code is arm64. Every bot-enabled device binary is arm64 IOS; the unsigned IPA matches the audited app byte for byte.

Data stays under the original EULA locally. Only whitelisted bundled engine/Legacy executable frameworks and the exact signed bundled Omni-bot core path can load. ## Resolved failures worth preserving

- macOS SDK: initial CLT 27.2 linker rejected arm64e.x1-macos; CMAKE_OSX_SYSROOT alone was overwritten. Third attempt pinned both CMAKE_OSX_SYSROOT and XCODE_SDK_PATH plus SDKROOT to Xcode's macOS SDK. Source builds pass.
- Submodule historical shallow fetch failed; explicit HTTPS fetch of the pinned gitlink fixed it. Public script checks clean pinned libs.
- Public UDP pack stalled at block 32768 because MSG_ReadShort sign-extends. Compare low wire 16 bits against a full local counter; distinguish first headers/redirect sentinel/rollover block zero, bound truncated headers. Live 32.71 MiB download passes on Mac and simulator.
- Darwin GL4ES lacks public GNU aliases; direct calls initially reached GLES3/ANGLE and produced black output. Force-include GL4ES private entry-point mapping in the iOS renderer. ES1 Legacy UI/game now renders through ANGLE Metal.
- Non-returning engine loop starved UIKit transactions. iOS initialization returns; CADisplayLink calls Com_Frame with reentry guard and activity pause. com_maxfps=0 actually clamps to 20, adding ~50 ms NET_Sleep per frame; 250 plus 60 Hz display pacing fixes native UI responsiveness.
- Apparent landscape blocker after three app-layout experiments was later traced to simulator sensor state: toolbar Rotate changed the display/bezel without selecting Device→Orientation→Landscape Right/Left. Both sensor orientations now work. This was new external-state evidence, not another speculative app fix.
- Resolution: direct drawableSize was overwritten by ANGLE; fitting UIView alone also failed. Pinned ANGLE source showed bounds×contentsScale behavior. Third fix sets contentsScale to requested width / layer width while keeping native presentation bounds. Real 960 rendering and live 1280 restart fill screen. Earlier failure images retained; the later menu/reconnect investigation is recorded below.
- Calling CUA getApp/getAXState after Quit silently relaunched the Mac app. Use process/session exit instead. Initial native menu/profile automation failed three attempts; prepared profile files on disk and drove console/gameplay input. Do not report that as a stalled engine shutdown.
